# Jazz Voicing Lab v0.2 設計メモ

利用者からの回答を受けて、MVP 0.1 を「両手コンピング + ウォーキングベースを、毎回ちがう響きで生成して DAW に持っていける道具」へ作り替えるための設計です。実装前の合意用ドキュメントです。

---

## 0. 用語の確認（回答8「ブロックコードだけの、意味がわからん」への回答）

- **ブロックコード（block chord）**: 和音の全部の音を、同じタイミングで同じ長さだけ鳴らす置き方。今の MVP がまさにこれで、1コードにつき「ジャーン」と1回鳴って終わり。だから MIDI を DAW に持っていっても、リズムがのっぺりしていて、そのままでは演奏に聞こえない。
- **コンピング（comping）**: 伴奏のこと。実際のジャズピアノは、和音を裏拍で切ったり、食い気味に入れたり、休んだりする。ここを作るのが v0.2 の主目的のひとつ。
- **ウォーキングベース**: 1拍に1音ずつ、主に隣り合う音や半音で歩くように動くベースライン。
- **ボイシング（voicing）**: 同じコードでも、どの音をどの高さに置くか、という配置のこと。

## 1. 何を作るのか（目的の再定義）

利用者の主目的は 3・4・6 だった。

| 番号 | 目的 | 設計への影響 |
| --- | --- | --- |
| 3 | iReal Pro のように毎回ちがう和音を鳴らしたい | ループ再生は維持。ただし「和音が変わる」だけでなく「リズムも毎周変わる」ところまでやる |

つまり v0.2 のゴールは **「進行を打ち込む → 演奏として成立したピアノ + ベースの MIDI が出てくる」** ことです。画面上の見た目より、書き出した MIDI の質が評価軸になります。

## 3. いちばん大きな設計変更：演奏イベント（Performance IR）を挟む

今のコードは「ボイシング（音の集合）」から、audio.ts と midi.ts がそれぞれ勝手に音の長さを決めています。これだとリズム・スウィング・ベロシティを足すたびに2箇所を直すことになり、試聴と書き出しが食い違います。

そこで中間表現を1つ挟みます。

```
コード進行テキスト
   ↓ parse
ParsedChord[]                        … 今もある
   ↓ 語彙モジュール群
VoicingCandidate[]（コードごとの候補）  … 今もある。両手対応へ拡張
   ↓ テイク探索（進行全体）
Take（各コードのボイシング確定）
   ↓ アレンジ（コンピング + ベース + 人間味）
PerformanceEvent[]  ★新設
   ↓                    ↓
  audio（試聴）        midi（書き出し）
```

```ts
export type TrackId = 'piano' | 'bass'

export interface PerformanceEvent {
  track: TrackId
  midi: number
  /** 曲頭からの位置（拍）。スウィングや食いを含めた最終的な位置 */
  startBeat: number
  durationBeats: number
  velocity: number   // 1–127
}

export interface Performance {
  events: PerformanceEvent[]
  totalBeats: number
  take: Take            // 表示用に、どのボイシングを選んだかも保持
}
```

試聴も書き出しも、この `Performance` だけを読む。**聞こえたものがそのまま書き出される**状態を保証します。

## 5. ボイシング生成（両手・厚め）

### 5.1 データ構造

```ts
export interface Voicing {
  family: string        // 'rootless-a' | 'quartal' | 'ust' ...
  label: string         // 画面表示用
  left: number[]        // 左手の MIDI 音（低い順）
  right: number[]       // 右手の MIDI 音（低い順）
  degrees: string[]     // left + right と同じ並びの度数
}
```

両手を別々に持つ理由は 3つ。
1. 手ごとに幅の制約が違う
2. 左手は下を支え、右手は色を出す、という役割分担でスコアを分けたい
3. トップノート（＝右手の一番上）の扱いが素直になる

### 5.2 両手の組み立て方

厚いボイシングを「テンプレート丸ごと」で持つと組み合わせ爆発するので、**下部構造 × 上部構造**の掛け算で作ります。

- **左手（下部構造）**: 3度と7度を必ず含む2〜4音。rootless A/B、シェル、4度2音、10度に開いたオープン型など。
- **右手（上部構造）**: 2〜4音。トライアド（アッパー・ストラクチャー）、4度堆積、クラスター、ドロップ2など。
- 左右の合計が希望音数（既定5〜7）に収まる組み合わせだけを採用。

これで語彙を1つ足すと、掛け算で候補が増えます。

### 5.3 演奏可能性チェック（playability.ts）

回答10で「避けたいものは無い」とのことですが、**物理的に弾けない/確実に濁る**ものだけは落とします。ここは好みの問題ではないので、設定でも外せない土台にします。

| チェック | 基準 | 理由 |
| --- | --- | --- |
| 片手の幅 | 12半音以内を基本、**最大16半音（長10度）** | 利用者が10度届くとのことなので、そこまで許可 |
| 片手の音数 | 4音まで | 5音は特殊なので第3段階 |
| 左右の重なり | 左手の最高音 < 右手の最低音 | 手が交差しない |
| 左右の隙間 | 12半音以内が基本 | 開きすぎると1つの響きに聞こえない |
| 低音側の濁り | 低音での狭い音程を禁止（低音程限界の表を使う。例：長3度は E3 より下に置かない） | ここより下は必ず濁る |
| 短9度の衝突 | ドミナントのルート上以外では減点、極端なものは除外 | 意図しない濁り |

「避けたい響き」が後から出てきたら、ここに設定つきのルールとして足せる構造にしておきます。

**片手10度について（フィードバック反映）**

10度まで届くなら、左手の選択肢がはっきり広がります。

- `1-7-3`（ルート・7度・3度を10度幅に開く）や `1-5-10` のような**開いた下部構造**が使える。狭いボイシングより濁りにくく、低いところに置けるので、両手で厚くしても飽和しにくい
- ただし全部を10度にすると、間の音が少なくなって逆に薄くなります。なので「10度まで許可」であって「10度を優先」ではない扱いにします。幅は広めを少しだけ加点する程度に留め、実際の選択はボイスリーディングのスコアに任せます
- 幅を広げると左手が低い方へ行きやすいので、低音側の濁りチェック（低音程限界）はこれまで以上に効きます。ここは必ず通します
- 16半音を超える配置（アルペジオで下から上へ転がす前提のもの）は、第3段階の検討事項にします

### 5.4 語彙レジストリ

```ts
export interface VocabModule {
  id: string
  label: string             // 画面の日本語ラベル
  description: string       // 「どういう響きか」の一行説明
  tier: 'core' | 'color' | 'modern'
  build(chord: ParsedChord, req: VoicingRequest): Voicing[]
}
```

画面ではチェックボックスで ON/OFF。既定は core + color を ON、modern は第3段階で追加。

## 6. テイクの選び方（回答7：進行全体で自然なもの）

今は「前のコードだけ見る貪欲法」なので、3コード先で行き詰まって不自然になることがあります。**ビームサーチ**に変更します。

1. 各コードで候補を上位 K 件（例 K=40）に絞る
2. 幅 B（例 B=24）のビームで進行の最後まで探索し、部分列のスコアを積み上げる
3. 最後まで残った経路のうち、上位からランダム性に応じて1本を抽選
4. これを 8 回まわして 8 テイクを作る（回答9：案は多いほうがいい）。同じテイクは除外

### スコア項目（重みは調整可能にする）

| 項目 | 内容 | 重み（初期案） |
| --- | --- | --- |
| ボイスリーディング | 各声部の移動量の合計。少ないほど良い | 1.0 |
| トップライン | 一番上の音の動き。2〜4半音の動きを最も高評価、同音の連続と7半音超の跳躍を減点 | 0.6（スライダーで 0〜1.5） |
| 音域の中心 | 設定音域の中心からの距離 | 0.3 |
| 語彙の多様性 | 同じ family が3回以上連続したら減点 | 0.4 |
| 音数の安定 | テイク内で音数がばらつきすぎたら減点 | 0.2 |
| 共通音の保持 | 前後で保たれる音があれば加点 | 0.3 |

回答4の「トップノートがなんとなくメロディのようになればいい」は、この**トップライン項目**そのものです。固定はしないので、スライダーを上げると「上の音が歌う」テイクが出やすくなります。

## 7. ウォーキングベース（追加要望）

別モジュール `bass.ts`。ピアノとは独立に生成し、別トラックへ。

- 音域: E1–G3（MIDI 28–55）。コントラバスの実音域に合わせる
- 基本は1拍1音の4分音符
- 拍ごとの役割:
  - **1拍目**: そのコードのルート（8割）。残りは5度や3度で、同じ音の繰り返しを避ける
  - **2・3拍目**: コードトーンかスケール音。直前の音から2半音以内で動くのを優先
  - **4拍目**: 次のコードのルートへの**アプローチ音**。半音上・半音下・スケール上の隣接音・次ルートの5度上、から選ぶ
- 1小節に2コードある場合は、各コード2拍で同じ考え方を縮める
- 方向転換: 同じ方向に5音以上続いたら反転を優先（延々と上がり続けるのを防ぐ）
- 進行全体でピアノと同じくビームサーチ的に選ぶ（局所的に破綻しないため）
- ON/OFF と、音量バランスを画面から調整可能に

ベースがルートを担うので、ピアノ側は rootless のままで成立します（回答2）。

## 8. コンピングのリズム（回答8）

`comping.ts` にパターンを持ちます。パターンは「小節内の、拍位置と長さの並び」。

```ts
export interface CompPattern {
  id: string
  label: string
  density: 'sparse' | 'medium' | 'busy'
  hits: { beat: number; durationBeats: number; accent: number }[]  // beat は0始まり
}
```

初期パターン例（4拍子）:

| 名前 | 位置 | 性格 |
| --- | --- | --- |
| チャールストン | 1拍目、2拍裏 | 定番。まずこれ |
| 裏拍2つ | 2拍裏、4拍裏 | 軽い |
| 食い込み | 前小節の4拍裏から入って伸ばす | 前へ進む感じ |
| 白玉 | 1拍目だけ長く | 休ませる |
| 密 | 4箇所以上 | 盛り上げ |
| 休み | なし | 抜く。連続させない |

- 小節ごとにパターンを重み付き抽選。「休み」の直後に「休み」は選ばない
- 密度スライダー（sparse ↔ busy）で抽選の重みを変える
- コードが変わる位置には必ず発音を1つ置く（和音が鳴らない小節を作らない）
- 食い込み（前小節の4拍裏で次のコードを先取り）は確率で発生させる。ジャズらしさの多くはここ

ループ再生時は、**ボイシングもリズムも**1周ごとに引き直します。

## 9. 人間味（swing / velocity）

`humanize.ts`。ここはすべて `PerformanceEvent` の生成時に適用します。

- **スウィング**: 8分裏の位置を、拍の 0.5 ではなく 0.62〜0.67 に置く。スウィング量をスライダーで 0（イーブン）〜100% に。テンポが速いほど既定値を 0.5 寄りにする
- **ベロシティ**:
  - ピアノ 基準 72、裏拍は +6 程度のアクセント、乱数 ±7
  - ベース 基準 84、1拍目 +5、乱数 ±5
  - 和音内でもトップノートを +4 程度上げる（旋律に聞こえやすくなる）
- **タイミングの揺れ**: ±10ms 相当の微小なずれ。和音内も完全同時を避け、下から数ms単位でずらす
- 「きっちり」トグルで全部 OFF にできるようにする（打ち込みの下敷きとして使うとき用）

## 10. MIDI 書き出し（回答4・6の本命）

現行は format 0 の1トラック。これを **format 1 のマルチトラック**に変更します。

| トラック | 内容 |
| --- | --- |
| 0 | テンポ、拍子、曲名などのメタ情報 |
| 1 | Piano（コンピング） |
| 2 | Bass（ウォーキング） |
| （0内） | コード記号をマーカーとして記録（DAW 上で位置がわかる） |

追加する書き出しオプション:

- **コーラス数**: 1〜8。各コーラスでボイシングもリズムも引き直すので、そのまま長さのある伴奏トラックになる
- **テイク指定**: 並んだ 8 案のうち、気に入ったものを選んで書き出し
- **ファイル名**: `進行名-テンポ-日付.mid`
- 手ごとにトラックを分けるかどうかは、第2段階で検討（分けたいという要望が出たら対応）

これで「DAW にドラッグして、ピアノ音源とベース音源を割り当てれば、そのまま下敷きになる」状態になります。回答6の自動化の中身はここです。

## 13. この設計で決め打ちしたこと（違ったら言ってほしい点）

1. **ピアノは基本 rootless のまま**。ベースがルートを弾くため。ただしベースを OFF にしたときは自動でルート入り候補に切り替える
2. **音数は 5〜7 を既定**。「めっちゃ」を上限8音と解釈。両手で8音を超えると、実際には弾けないか濁る
3. **トップノートは制約ではなくスコア**。固定したくなったら、後から「メロディ入力欄」を足せる構造にはしておく
4. **テイクは8案**。「多いほうがいい」だが、画面に並べて比較できる上限として8にした
5. **スウィングは既定 ON**。イーブンにしたい曲のためにスライダーで 0 にできる
6. **片手の幅は最大10度**（フィードバック反映済み）。ただし10度を毎回使うのではなく、届く範囲として開放するだけ

## 15. 「厚さ」を軸にする（Bud Powell の回答を受けて）

利用者から名前が挙がったのは Bud Powell で、「2音とかやけど」という補足つきでした。調査結果は [VOICING_RESEARCH.md §8](VOICING_RESEARCH.md) にまとめています。

### 15.1 ここで矛盾が1つ出た

- 回答1・3では「**両手で厚いコンピング**」「音数は**めっちゃ**」
- 好きなピアニストは「**左手2音**」の Bud Powell

これは正反対です。ただ、どちらかが間違いというわけではなく、**用途が違う**だけだと考えます。

- 厚い両手 = 伴奏そのものを作りたいとき（DAW の下敷き、鳴らして楽しむ）
- Powell の2音 = 上を空けたいとき（右手でソロを弾く、DAW でメロディを乗せる）

なので「どちらを作るか」ではなく、**厚さ（density）を1本の軸として持ち、プリセットで切り替える**構造にします。回答5の「ぜんぶ入れてほしい」とも整合します。

### 15.2 厚さプリセット

| プリセット | 中身 | 想定用途 |
| --- | --- | --- |
| Powell（2音） | 左手のみ `1-7` / `1-3` / `1-10` / `1-6`。右手は完全に空ける | 上にソロやメロディを乗せる前提。DAW で自分のラインを書くときの土台 |
| シェル+（3音） | `1-7-3`、`1-7-10` など | 少し厚みが欲しいが、まだ上は空けたい |
| 標準（4〜5音） | 現行の rootless 中心 | 普通のコンピング |
| 厚め（5〜7音） | 両手。下部構造 × 上部構造 | **既定**。回答1・3の「めっちゃ」 |

スライダー1本ではなくプリセットにするのは、音数だけ変えても Powell にはならないからです（後述）。

### 15.3 Powell プリセットは音数だけでは作れない

Powell らしさは、**ボイシング・音域・リズムの3つセット**です。このプリセットを選んだときは以下も同時に切り替えます。

1. **ルートを入れる**。Powell voicing は必ずルートが最低音。「ベースがいるから rootless」の例外扱いにする（歴史的にもベース入りのトリオでルートを弾いている）
2. **音域を下げる**。左手は F2〜C4 あたり。7度・10度という広い音程なので、低く置いても濁らない
3. **リズムを変える**。伸ばさず短く切る。裏拍と食い込みを増やす。休符を多めに。`comping.ts` に Powell 用のパターン群（短いジャブ中心、休みの確率高め）を用意する
4. **右手を空ける**。右手トラックは何も鳴らさない

つまり density プリセットは、ボイシング語彙・音域・コンピングパターンをまとめて切り替える**シーンの切り替え**として実装します。

### 15.4 10度の件とつながる

片手の幅を10度まで許可した判断（13章の6）は、Powell の `1-10` shell とそのまま一致します。10度が届くなら、この語彙は制約なしで実装できます。順番としても都合がいいので、`vocab/powell.ts` は**第1段階**に入れます（当初 modern 枠で第3段階に置いていたものを前倒し）。

### 15.5 ビバップ寄りの副産物

Powell を入り口にすると、次に自然につながるものが見えます。第2段階以降の候補として置いておきます。

- Barry Harris 系のシェル＋装飾
- ビバップらしい速いテンポでの挙動確認（テンポ200超で破綻しないか）
- ドラム（ライド＋ハイハット）。ビバップは特にリズムが命なので、要否の判断材料になる
