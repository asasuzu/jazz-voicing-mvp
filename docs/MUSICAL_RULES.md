# 音楽的な要望をどこに書くか

利用者から「なんか行ってほしい音があるねん。それって学習はたぶんできひんから、口頭で足繁く言うしかないんかな」という質問があった。

**答え: 言い直す必要は無い。一度言ってもらえれば、規則として書いて固定できる。**

このアプリは学習型ではないので「なんとなく覚える」ことはしないが、逆に言えば**書いたことは絶対に忘れないし、勝手に揺らがない**。以下はそのための置き場所。新しい要望が来たら、どれかに1行足す。

---

## 使い分け

| 要望の形 | 置き場所 | 性質 |
| --- | --- | --- |
| 「このコードではこの音を使ってほしい／使ってほしくない」 | `TONE_PRIORITY`（`src/music/constants.ts`） | 数値の重み。ランダム性で揺れる |
| 「この動きは絶対にやめてほしい」 | `violatesVoiceLeadingRule`（`src/music/voicings.ts`） | 候補から除外。ランダム性でも破れない |
| 「この語彙をもっと／あまり使わないで」 | `POWELL_FAMILY_BIAS` など語彙の重み（`src/music/constants.ts`） | 数値の重み |
| 上記のどれでも、**二度と戻ってほしくない** | `tests/voiceleading.test.ts` にケースを足す | 壊れたらテストが落ちる |

### 重みか、除外か

重要な違いがある。

**重み（スコア）はランダム性ですり抜ける。** 実例: 「Dm7の9th(E)がG7の5th(D)へ行くのは変」という指摘に対して、最初は重みだけで対応した。結果、randomness 0 では100%守れたが、既定の 38% では15〜20%の確率で破れた。7回に1回は指摘された音が出る状態。

**ランダム性は色を変えるためのもので、規則を壊すためのものではない。** 「絶対にやめてほしい」ものは候補から外す。重みの調整で粘らない。

ただし、外しすぎると候補が消えて「毎回同じ」になる。除外は**文脈つき**にするのが安全（下記の実例を参照）。

---

## 実例1: ドミナントの5度

利用者の言葉:

> ルールはある(たぶん)
> **ドミナントで5thはかなり使わん**
> てのが、ルールかなとても雑に言えば

「絶対に使わない」ではなく「かなり使わん」。なので**禁止ではなく率で管理する**。実測で 49.3% → 3.6% にした。残りは UST bIII（Ebメジャートライアド = #9, 5, b7）のように、5度を含むが実際に使われる形。

対応は3箇所に分かれた。**1箇所直して測ったら40%残っていた**ので、犯人を特定しながら順に潰した。

| 出どころ | 対応前 | 対応 |
| --- | --- | --- |
| Quartal（4度堆積） | 100% | 機能するドミナントから外した。5音積むと構造上必ず5度が入る。そもそも4度堆積は響きが曖昧で、機能するドミナントには向いていない（sus7には残した。4度が和音構成音なので本来いちばん合う） |
| UST Im（1 #9 5） | 100% | ドミナントの表から外した。ベースがルートを弾く前提だと、ルートの重複と5度を足すだけで、増える色は#9のみ |
| Rootless のテンションプール | — | `['9','13','5','3']` から `5` を削除し、`#11` を足した |
| 記号付きドミナント（7b9等）の音数埋め | — | 埋める順を `13 → #11 → 9 → 5` にして、5度を最後の手段にした |

副作用として、**語彙の多様性はむしろ増えた**（使われるUSTが5種から9種へ）。5度を含む候補が場所を占めていた。

### 重みだけでは足りなかった話



最初は `TONE_PRIORITY` の重みだけで対応した。

```ts
dominant7: {
  9: -2.0,  // 13th。優先する
  7: 2.5,   // ナチュラル5th。避ける
  2: -0.2,  // 9th
}
```

値の目安は **1.0 = 声部が1半音動くのと同じくらい嫌**。randomness を上げても守ってほしいものは 2.0 以上でないと抽選をすり抜ける。

根拠は VOICING_RESEARCH.md §3（ベースがルートを弾く前提では5度の情報量が乏しく、13thへ置き換えるのが実用的）。

## 実例2: 9度を5度へ落とさない（文脈つきの除外）

指摘:「Dm7の9th(実音E)が5th(実音D)にいくのが変。G7側を13th(実音E)もしくはb13th(実音Eb)にして」

最初は「ドミナントでナチュラル5度を含み13thを含まない候補を全部外す」という無条件の規則にした。**これは行き過ぎだった** — UST bIII（Ebメジャートライアド = #9, 5, b7）のように、実際に使われる形まで消えてしまう。

なので文脈つきにした。

> 前のコードに、このコードの13th（または b13th）として保持できる音が鳴っているときに限り、その音を捨ててナチュラル5度へ動く候補を外す。

これで、

- Dm7 → G7 のように保持できる音があるときは、必ず 13th か b13th になる
- 単体の G7 では UST bIII も使える

計測結果（Dm7に9thがある回のうち、指摘された形が出た回数）:

| randomness | 対応前 | 重みだけ | 文脈つき除外 |
| --- | --- | --- | --- |
| 0 | 0% | 0% | 0% |
| 0.38（既定） | 45% | 15% | **0%** |
| 0.7 | — | 20% | **0%** |
| 1.0 | — | 16% | **0%** |

そして実際の行き先の分布は、13th(E) が大半、たまに b13th(Eb)。どちらも指摘で許容された音。

## 要望をもらうときにあると助かる情報

「変」とだけ言われても直せるが、以下があると一発で決まる。

1. **どのコードからどのコードへ**（例: Dm7 → G7）
2. **どの音がどの音へ行ったのが変か**（例: 9thのEが5thのDへ）
3. **代わりにどうあってほしいか**（例: 13thのE、またはb13thのEb）

3が特にありがたい。「変」だけだと、避けるべき形は分かっても、**行き先の選択肢**が分からない。今回は「13thもしくはb13th」と幅をもらえたので、毎回同じ音にならずに済んだ（13thが大半、たまにb13th、という分布にできた）。

逆に、口頭で繰り返す必要があるのは「この曲のこの箇所だけこうしたい」という**一回性のもの**だけ。一般化できる規則なら、ここに書けば終わり。
