# フィードバック 01 — 第1段階を実際に聴いてもらった結果

公開版を利用者に触ってもらった結果と、そこから決まった修正方針。**実装はまだしていない**（次にやることの一覧）。

---

## もらった内容

1. ベースがすごい。初期の進行が3小節なのもあいまって、今どこを弾いているのか全然わからない（「逆にかっこいい」とのことだが、形が見えないのは問題）
2. **全然バドっぽくない。7度と10度をめっちゃ使うようにしてほしい**
3. 何コーラス目からか `Dm7 G7 CM7` が変になる（バグではないか）
4. **Powell で Dm7 に シ(B) が入るのが変**

---

## 1. 形が見えない（優先度: 高）

### 何が起きているか

2つの原因が重なっている。

**(a) 既定の進行が3小節**。`DEFAULT_PROGRESSION = 'Dm7 G7 | Cmaj7 | A7alt'`（[src/App.tsx:12](../src/App.tsx:12)）は3小節なので、ループすると3小節周期になる。ジャズの曲は4小節単位が基本なので、耳が小節を数えられない。

**(b) ベースが小節の頭を主張していない**。ウォーキングベースは「1拍目にルート」を8割の確率で置いているが、**どの1拍目も等しく扱っている**。実際のベースは、コーラスの頭や4小節の区切りでルートを強く置いて、形を示す。

### 決めたこと

- 既定の進行を4小節にする。`Dm7 G7 | Cmaj7 | Em7 A7 | Dm7 G7` のような、ii-V が繰り返されて頭に戻る形
- ベースに**小節位置の概念**を持たせる。コーラスの1小節目の1拍目は必ずルート（確率1.0）、それ以外の小節の1拍目は現行どおり0.8
- コーラスの頭のベースのベロシティを少し上げる（`VELOCITY.bass.downbeatAccent` とは別に、コーラス頭用の加算を足す）

「かっこいい」と言われている自由さは殺さず、**基準点だけ立てる**方針にする。

## 2. バドっぽくない（優先度: 高）

### 原因は特定できた。スコア関数の「多様性」項

[src/music/score.ts:52](../src/music/score.ts:52) の `varietyPenalty` が、**同じ family が続くことを減点している**。

```
直近3つに同じfamilyが2回以上あれば +1、3回とも同じなら +2
```

これは厚いボイシングでは正しい（同じ型が続くと単調になる）。しかし Powell では**逆**。Powell の左手は R7 と R3/R10 をひたすら繰り返すのが様式そのもので、「毎回ちがう型を選ぶ」と Powell ではなくなる。

つまり、第1段階で汎用のスコアをそのまま Powell に適用したのが誤りだった。

### 決めたこと

- **Powell / shell3 では `varietyPenalty` を無効にする**（重み0）。様式として反復が正しいため
- **R7 と R10 を優先する重みを入れる**。利用者の要望どおり、この2つが Powell の中心。`constants.ts` に語彙ごとの選好重みを追加する

```ts
export const POWELL_FAMILY_BIAS: Record<string, number> = {
  'powell-r7': -1.2,    // 負の値 = 選ばれやすい
  'powell-r10': -1.0,
  'powell-r3': 0.4,     // 低い位置の狭い3度は Powell が避けた響き。控えめに
  'powell-r6': 0.6,
}
```

- **R3（近接の3度）を積極的に減らす**。Powell が広い音程を使った理由は「低い位置で濁らないため」（[VOICING_RESEARCH.md §8](VOICING_RESEARCH.md)）なので、3度を使うなら R10 のほうが様式に合う。R3 は音域の上のほうでのみ許可する案も検討する

## 3. 何コーラス目からか変になる（優先度: 高・要調査）

「何コーラス目**から**」という言い方から、**1周ごとに何かが蓄積している**と考えられる。単発のランダムの当たり外れではない。

### 疑っている順

**(a) 再生スケジューラの時刻が後ろ倒しになっている（本命）**

[src/music/render/audio.ts](../src/music/render/audio.ts) の `startPerformanceLoop` は、次のコーラスの開始時刻を `nextStart += chorusSeconds` で積み上げ、`setTimeout` を `(chorusSeconds - 0.4) * 1000` で仕掛けている。

ここに **`nextStart` が現在時刻より過去になっていないかの確認が無い**。タイマーが遅れた場合（タブの間引き、GC、あるいは毎コーラス走るビームサーチ自体が重い場合）、`nextStart` が `ctx.currentTime` を下回り、**そのコーラスの音が全部「過去の時刻」で予約されて一斉に鳴る**。これは「変になる」の聞こえ方と一致するし、ずれが累積するので「何コーラス目から」とも一致する。

対策案: `nextStart = Math.max(nextStart, ctx.currentTime + 0.05)` を入れ、ずれたぶんはその周で吸収する。

**(b) オシレーターの後始末が追いつかず負荷で崩れる**

`activeOscillators` は `onended` で除去しているが、ループが続くと配列が伸び続ける可能性がある。長時間再生でのCPU負荷を確認する。

**(c) ボイシング側の問題**

`randomness` が効いた結果、まれに極端な候補が選ばれている可能性。ただしこれは周回に依存しないので、「何コーラス目から」の説明にはならない。優先度は低い。

### 調査の手順

1. 各コーラスの先頭で `ctx.currentTime` と `nextStart` の差をログに出す。差が縮んで0に近づいていれば (a) で確定
2. (a) なら上記の下限クランプを入れて、20コーラス以上流して再現しないことを確認する
3. それでも再現するなら (b) を測る

## 4. Powell の Dm7 に シ(B) が入る（優先度: 高・原因確定）

### 原因

[src/music/vocab/powell.ts:52](../src/music/vocab/powell.ts:52)

```ts
const SIXTH_QUALITIES: ChordQuality[] = ['major', 'major7', 'minor7'] // minor7はm6として使う
```

`minor7` に R6 を許しているので、Dm7 に対して `D + B`（1と6）が作られる。これは Dm6 の響きであって Dm7 ではない。ii-V-I の ii として鳴らすと、コードを決定づける b7（C音）が消えるため、利用者の言うとおり「変」。

仕様書 §4 の「R6 → major, major7, minor7（m6として）」という記述が誤りだった。

### 決めたこと

- **`SIXTH_QUALITIES` から `minor7` を外す**。R6 はトニックのメジャー系（`major`, `major7`）のみ
- 仕様書 §4 の表も直す
